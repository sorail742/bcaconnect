1. Synthèse exécutive

BCA Connect est une marketplace fintech/logistique pour les chaînes d'approvisionnement en Guinée et en Afrique de l'Ouest. Le parcours principal est opérationnel de bout en bout :

Catalogue → commande → paiement/séquestre → livraison GPS → litige → crédit → SAV → achats groupés

Le projet est porté par une équipe de 2 développeurs travaillant en parallèle sur des postes locaux indépendants, synchronisés via Git.

2. Contexte et vision

BCA Connect vise à devenir une centrale d'achat virtuelle reliant ménages, TPE/PME, fournisseurs, banques, transporteurs et techniciens. Les piliers du projet sont :

  • Centralisation du catalogue multicatégorie (38 catégories BCA)
  • Paiements sécurisés avec séquestre (escrow) et Mobile Money Guinée
  • Logistique GPS, livraisons groupées et 3 tiers de livraison
  • Crédit et financement partenaire banque
  • Litiges interactifs et médiation IA
  • SAV, garanties et maintenance terrain (technicien)
  • Achats groupés ONG/B2B

5. Phase 1 — Conception & prototypage ✅

Référence : backend/phase du developpement.md — Livrables : prototype catalogue/commandes/paiements.

5.1 Fondations

  • Architecture backend/frontend structurée
  • Schéma SQL Phase 1 (UUID, séquestre, split payment par fournisseur)
  • Modèles MVP : User, Wallet, Store, Product, Category, Order, OrderItem, Transaction
  • Table verifications_otp + service OTP (inscription, paiement, retrait)

5.2 Authentification

  • JWT RS256, Google OAuth, 2FA TOTP, rotation refresh token
  • RBAC : authMiddleware, grantAccess, authorize
  • Routes OTP : POST /auth/otp/request, POST /auth/otp/verify

5.3 Catalogue & commandes

  • CRUD produits fournisseur (ownership), gestion boutique, admin catégories
  • Panier Zustand, checkout wallet / MM (simulation) / COD
  • RBAC : seuls client et admin passent commande
  • Séquestre automatique ; stock MM différé jusqu'à confirmation paiement
  • Mode hors ligne : COD + flag mode_resilience
  • Tests : tests/orders.test.js

13. Parcours de démonstration

  1. Client : marketplace → panier → checkout wallet → /orders → /tracking
  2. Fournisseur : valider commande → marquer « prêt »
  3. Transporteur : accepter mission → GPS → OTP → vérifier wallet
  4. Banque : /bank/credits → approuver (npm run seed:pending-credits)
  5. Litige : signalement → réponse → résolution admin
  6. SAV : garanties → maintenance → technicien complète mission
  7. Achats groupés : /group-purchase → join wallet → clôture
  8. Admin : /admin/logistics, /admin/disputes, /admin/financial-reports (export PDF)
  9. Hors ligne : couper réseau → checkout COD → reconnecter → sync

Démarrage local (équipe — recommandé)

# Terminal 1 — Backend (SQLite auto)
cd bcaconnect
./scripts/dev-backend.sh

# Terminal 2 — Frontend
cd frontend && npm run dev

# Seeds (première fois ou après migration)
cd backend && npm run seed:accounts
npm run seed:recharge-wallets

Démarrage Postgres (optionnel — Phase 3)

./scripts/docker-dev.sh          # nécessite accès Docker
cd backend
export DATABASE_URL=postgresql://bca_user:bca_password@localhost:5433/bcaconnect
npm run verify:postgres
PORT=5001 npm run dev

14.5 Verdict final

BCA Connect est une plateforme pilote bêta fonctionnelle et documentée.

Les Phases 1 et 2 du cahier des charges sont clôturées côté développement (commit 9fece84). Le parcours métier principal est validé par 69 tests automatisés. La Phase 3 (lancement national) est amorcée : scripts infra, SMS stub, exports admin, guide équipe.

Le lancement production nécessite encore : clés CinetPay live, provider SMS, déploiement PostgreSQL/Redis, plan UAT et campagne pilote utilisateurs réels.
